# 40 · Harbor 开发预算与防空转约束

日期：2026-11-03。本轮只补充开发指南，没有安装 Harbor、修改实现或运行评测。

用户希望 Cursor／Opus 能连续开发，同时避免无限重试、等待与重复检查消耗开发额度。已在 [Harbor 集成指南](../harbor-integration-plan.md) 的 2.1～2.4 增加：

- 单批最多 180 分钟，最后 10 分钟收口；G0～G6 可以分批完成，不因到限降低验收标准。
- 同一故障首次失败后最多两次有依据的修复重试；环境准备累计等待最多 25 分钟，单个安装／拉取／构建最多 10 分钟。
- 网络、测试和真实 Docker 验收分别限时；长任务每 30～60 秒观察，后台 session 不等于进程受限，超时必须处理自有进程与容器。
- 本地工作账本记录截止时间、累计等待和尝试；上下文恢复、自动续跑不能重置预算。
- 限制日志输出和重复测试，先定向后全量；阻碍到限转离线工作，总预算到限交付草稿与明确的未完成清单。

第 12 节的 Cursor 启动任务和最终验收清单也已同步。文档不能设置 Cursor 账户硬限额或自动关闭会话；会话时限依赖 Agent 遵循，命令时限应通过实际执行工具落实。没有可核实开发 token 统计时必须标为未知，不能把实验 token_limit 当开发额度限制。

本轮验证范围是文档链接、代码围栏和 diff 空白检查；未运行单元测试、Docker 或收费模型。后续开发者仍需实现并验证运行时取消／超时功能，本轮没有声称其已经可用。
