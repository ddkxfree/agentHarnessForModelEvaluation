## 必须修复的问题

### R1 [P1] fix-mean 的 NaN 错误实现仍然通过

位置：`src/harness/tasks/terminal_data/fix-mean/tests/test.sh:27`。

让 `mean`、`median` 都返回 `float("nan")`，当前验证程序仍输出 `PASS`，退出码为 0。`abs(got - expected) > 1e-9` 无法拒绝 NaN。

上一轮修的是 `Score.value` 的有限性与问答数字归一化；这两项均无法捕获验证脚本已经错误生成的合法分数 1.0。原脚本本轮没有改动。

验收：拒绝 NaN、正负无穷及无效返回类型；正确参考实现通过，错误实现失败；保留 Oracle 全过、不操作全失败的 Docker 回归。验证脚本变化应进入任务指纹。

### R2 [P2] decimal_exact 仍会舍入不同的小数

位置：`src/harness/core/scorer.py:59`。

`Decimal.normalize()` 使用当前 decimal context 的精度，默认 28 位，并非任意精度的无损格式化。本机复现：

```text
标准答案：0.12345678901234567890123456781
模型答案：0.12345678901234567890123456782
两者归一化：0.1234567890123456789012345678
当前得分：1.0
```

验收：使用不受全局 context 精度影响的精确比较／规范化；不同长小数不得相等，相同数值的不同尾零形式应相等；覆盖不同 decimal context 精度；修正 normalization 版本标识，让指纹识别行为变化。

### R3 [P2] 评分器修复后重评，旧 scorer_error 无法恢复

位置：`src/harness/analysis/rescore.py:40`、`src/harness/core/types.py::classify`。

先让 scorer 抛 KeyError，保存运行；再替换成正确评分器，执行不调用模型的 rescore。本机复现：

```text
score.value = 1.0
outcome = scorer_error
error_kind = scorer
error = KeyError: 'broken scorer'
summary.accuracy = 1.0
```

原因是 rescore 更新 score，却没有处理上次评分失败的 error/error_kind；classify 优先采用旧错误归类，导致得分和故障统计矛盾。

验收：成功重评后清除当前评分状态中的旧评分故障，并把旧故障保留在历史；不得误清除生成／求解阶段的故障；重评再次失败应按样本记录 scorer_error、继续其他样本，检查返回类型与分数合法性。不要让有输出但求解失败的样本因重评意外成为完整成功。
