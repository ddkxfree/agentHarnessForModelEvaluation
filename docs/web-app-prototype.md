# Agent Eval Studio：六模块原型设计与 Cursor 提示词

日期：2026-11-05。状态：设计与开发交接，尚未实现原型。

## 1. 产品定位

智能体评测与可观测工作台：选择评测集、配置模型与 Agent、观察运行、回溯任务轨迹、比较实验表现。

第一版使用明确标注的演示数据完成可运行、可交互的 Web 原型，后续连接现有 Harness／Harbor 后端。不调用真实模型、不启动 Docker、不产生费用。训练数据管理和模型后训练留待后续。

核心路径：选择评测集 → 配置实验 → 模拟运行 → 查看轨迹 → 对比实验。

## 2. 视觉方向

简洁、美观、大方，像排版精致的专业研究工具。浅灰或暖白背景、白色内容区域、细边框、低饱和蓝色强调色；充分留白、清晰字体层级、数字对齐，命令和日志使用等宽字体。

中文界面，必要技术字段保留英文；桌面优先，兼顾窄屏。避免营销横幅、大面积渐变、玻璃拟态、过多阴影和嵌套卡片。状态同时使用文字与颜色，图表服务于分析。

## 3. 六个一级模块

| 模块 | 页面内容 | 核心操作 |
|---|---|---|
| 工作台 | 最近实验、运行状态、成功率、token、耗时 | 找到运行中及待分析实验 |
| 评测集 | 简介、版本、任务列表、能力标签、运行要求 | 选择任务并创建实验 |
| 实验中心 | 实验列表、新建实验、进度、结果 | 配置、启动、取消、查看详情 |
| 轨迹分析 | 跨实验轨迹列表、单题时间线、评分证据 | 筛选、搜索、回溯、左右对照 |
| 实验对比 | 配置差异、效果、消耗、进退步样本 | 比较模型或版本，定位变化 |
| 模型与连接 | 模型、Agent、执行环境及连接状态 | 管理演示配置 |

### 3.1 工作台

展示正在运行和最近完成的实验、所选范围的成功率和用量，以及需要关注的失败、环境异常和预算耗尽。可点击进入对应实验或筛选结果。

指标标明统计范围，不同评测集的成绩不能混成无解释的总分。

### 3.2 评测集

列表与详情包含名称、介绍、版本、任务数量、能力标签、运行要求和兼容状态。支持查看任务，选择明确任务集合创建实验。

兼容状态标注为演示，不暗示仓库固定 Harbor 版本已支持或验收所有最新功能。

### 3.3 实验中心

实验列表支持搜索，按状态、模型、Agent 和评测集筛选，以及选择两个实验进行对比。

新建实验字段：评测集及版本、任务范围、模型、Agent、执行环境、重复次数、并发和运行限制。

可提供自然语言配置演示：“用模型 A 跑 5 道终端题，每题 3 次，并发 2。”只解析明确支持的示例，标注“演示解析”，输出可编辑配置表单。不支持的输入明确提示。

实验详情展示配置、进度、样本列表、用量、耗时和事件。模拟运行由统一状态驱动，支持开始、完成、取消；取消后计时和进度停止。点击样本进入对应轨迹，保留返回实验入口。

### 3.4 轨迹分析

**必须保留独立一级导航，不能只作为实验中心的子页面。**

两个入口：侧栏进入跨实验轨迹列表；实验详情直接进入指定样本轨迹。两者复用数据与组件。

列表按实验、模型、Agent、评测集、任务结果和结束原因筛选。

详情采用三栏布局：

| 区域 | 内容 |
|---|---|
| 左侧 | 任务说明、步骤导航、错误定位 |
| 中间 | 模型消息、工具调用、工具返回时间线 |
| 右侧 | 评分证据、结束原因、token、耗时 |

支持折叠、搜索、复制命令、展开长日志、定位错误步骤，以及同一任务两条轨迹左右对照。窄屏改为分区或抽屉。

准备三种完整演示案例：正常成功；Git 合并冲突后预算耗尽；环境准备失败且未发生模型调用。

只展示已记录的消息与行动，不虚构内部思考。日志回放不代表恢复执行现场；逐步用量缺失时不伪造，最终汇总不能伪装成实时指标。

### 3.5 实验对比

支持不同模型横向比较，以及同一模型或 Agent 的版本比较。展示配置差异、成功率、输入／输出 token、耗时和费用估算。

配对样本分为失败→成功、成功→失败、都成功、都失败。未匹配、取消和环境异常另行展示，不强行归入模型答错。可点击查看配对轨迹。

成功率变化使用“百分点”。能力维度有任务标签依据，显示样本数；没有统计数据时不编造置信区间。任务集、Agent 或预算不同要提示具体差异，不能把变化全部归因于模型。

### 3.6 模型与连接

展示模型、Agent、Native／Harbor 来源和执行环境的演示配置。凭据使用占位符，不请求或保存真实 API key。连接测试明确为模拟。

后续真实接入以仓库固定版本和已验证能力为准，尚未接入的能力明确标注。

## 4. 指标与数据要求

| 指标 | 展示口径 |
|---|---|
| 得分、成功率 | 标明任务范围、分母和评分口径 |
| 状态 | 完成、模型失败、环境异常、取消分别统计 |
| Token | 区分输入、输出、缓存，说明缓存是否已计入输入，避免重复求和 |
| 费用 | 区分实际与估算，估算附价格口径与日期 |
| 耗时 | 区分实验墙钟时长与任务耗时之和 |
| 步数、工具调用数 | 说明步的定义，不默认两者相等 |
| 缺失值 | “未记录”“不适用”与真实的 0 分开 |

所有页面共享统一演示数据与状态，保证汇总、明细、轨迹及对比一致。日志按不可信文本安全展示。

## 5. 工程与验收

优先沿用已有前端方案；没有则使用 React＋TypeScript＋Vite。数据类型、模拟服务与界面组件分层，方便后续替换真实 API。

准备加载、空数据、错误、长文本及字段缺失状态。按钮有真实行为，未实现入口禁用并说明；支持基本键盘操作，图标按钮有可访问名称。

验收路径：

1. 评测集选择任务，创建实验并修改配置。
2. 开始模拟运行，查看进度；另测取消后停止更新。
3. 打开轨迹，搜索命令并定位失败原因。
4. 从轨迹一级入口筛选同一记录，确认内容一致。
5. 对比两个实验，查看配置差异及配对轨迹。
6. 检查刷新、浏览器返回、窄屏、长日志及缺失值。

交付可运行代码、启动命令、验收结果、模拟范围和后端接入点。执行必要检查并按仓库约定更新进度。本文件不代表前端已实现或已通过验收。

## 6. Cursor 提示词一：生成完整原型

确保本文件在 Cursor 工作区中，然后复制以下提示词：

```text
请实际开发 Agent Eval Studio（智能体评测工作台）的 Web App 原型。

先阅读 AGENTS.md、docs/roadmap.md 和 docs/web-app-prototype.md。
以原型设计文档为产品范围与验收依据，检查已有仓库结构，
选择不影响 Python 核心的前端实现位置。

保留六个一级模块：工作台、评测集、实验中心、轨迹分析、
实验对比、模型与连接。轨迹分析必须有独立列表与详情，
也可以从实验详情直接进入，复用同一份数据和组件。

本轮用清楚标注的演示数据完成交互，不调用模型、不启动 Docker、
不产生费用、不请求或保存真实 API key。
自然语言配置只做明确示例的演示解析，输出可编辑表单。

视觉要求：简洁、美观、大方、专业；浅色背景、细边框、充分留白、
清晰排版、低饱和蓝色强调。避免营销横幅、渐变和过度卡片化。
重点打磨实验详情、轨迹时间线和双实验对比。

优先沿用已有前端技术；没有则使用 React、TypeScript、Vite。
用统一类型、模拟数据和状态支撑全部页面，预留后端接口边界。
缺失值不能填零，环境异常不能冒充模型失败，演示不能称真实结果。

先完成整体交互，再精修视觉，最后按设计文档第 5 节逐项验收。
请交付实际可运行代码，不要只回复计划或设计说明。
完成后提供启动命令、验证结果、模拟范围与待接入能力，
执行必要检查并按仓库约定记录中文进度。
```

## 7. Cursor 提示词二：视觉精修

```text
请在现有 Agent Eval Studio 原型上进行视觉精修，保留六个模块和功能范围。
阅读 docs/web-app-prototype.md，按其中视觉方向实际修改页面。

统一标题、工具栏、表格、按钮、表单、间距和字体层级。
减少嵌套卡片、重复边框与阴影，突出关键指标，弱化次要信息。
数字对齐、单位与精度一致；长模型名和日志提供完整查看方式。
图表标明单位、范围和样本数，颜色语义全站一致。
轨迹突出工具名、命令、错误和评分证据，支持展开或全屏查看。
检查桌面和窄屏布局，不增加无意义模块，不改变数据口径。
演示标识清楚但克制。

请实际检查页面效果并修复问题，简要说明改进与验证结果。
```

## 8. Cursor 提示词三：交互验收

```text
请按 docs/web-app-prototype.md 验收现有原型，并实际修复问题。

走通：工作台 → 评测集 → 新建实验 → 修改配置 → 模拟运行 →
单题轨迹 → 查找失败原因 → 双实验对比 → 配对轨迹。
另从“轨迹分析”一级导航搜索同一记录，确认数据和入口行为一致。

检查取消后进度停止；搜索筛选及清除正常；刷新和浏览器返回合理；
长日志与窄屏不破坏布局；缺失值不填零；环境异常与模型失败分开；
汇总与明细一致；只配对匹配样本，未匹配样本单独列出；
所有按钮有行为，未实现功能禁用说明；不把模拟写成真实验收。

执行构建和必要检查，交付已验证流程、启动命令与剩余限制。
```
