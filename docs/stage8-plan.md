# 阶段八：评测集接入 Agent 开发指引

状态：开发计划，尚未实现或验收。先阅读 `docs/roadmap.md`、`docs/next-stages.md` 和本文件。继续按 Opus 开发、Codex 评审推进。

## 第一版目标

给接入 Agent 一份固定版本的评测集说明和样例，让它生成 Task adapter、候选测试与配置，运行检查并根据错误做有限次修正，最终交付可人工评审的 diff。

第一版只支持一种明确的小数据格式、一个新 Task。先用冻结的本地外部格式样例把链路做完整；不要求任意网址自动接入、自动下载整个基准、完整平台重构或自动合并代码。

“接入 Agent”是程序中可调用的工作流。Opus 手动写出一个 adapter、一个固定模板生成器，或只让模型输出一次代码，都不能单独算完成 Agent 化。

## 与前面阶段的关系

- 复用 Model／Generate、重试、超时、缓存、轨迹和现有 Solver／沙箱能力；优先包装已有 Agent，不再另造大型框架。
- 候选任务沿用 `Task`、`Sample`、DatasetSpec、Scorer／SandboxScorer 和注册约定。
- 验收任务接入时不改 core。若实现接入工作流本身确实需要通用基础设施调整，应单独说明，不能把针对某个数据集的分支塞入 runner。
- 阶段六 J1／J2 小补修可以先用独立提交完成；阶段八可先设计与开发，不依赖真实 Judge 校准或真实消融结果。

## 输入与范围

使用一份显式接入规格，至少包含：

- 任务名；来源路径／说明文件；固定 revision 或本地源文件内容哈希；
- 样例数据、字段含义、划分方式、官方评分规则及允许的依赖；
- 生成目录，以及最大模型步骤、修复次数、执行时间与 token 预算；
- 模型配置。真实运行由用户提供本地端点或外部 API，密钥不写入生成代码和归档。

第一轮提供冻结的小样例包：说明、非本平台格式的数据、可信的正确／错误输出，以及独立验收规则。单元测试使用该包，不需要联网、密钥或模型下载。官方答案或已有评分规则有歧义时，输出具体未决问题，不自行改规则。

## 必须存在的执行循环

1. 阅读说明和样例，生成字段映射及接入计划。
2. 在隔离候选目录写出 adapter、候选测试和运行配置。
3. 执行导入、格式和功能检查，记录结构化结果。
4. 失败时将诊断摘要返回 Agent，让它修正候选实现；有明确次数／时间上限，防止无限循环。
5. 独立验证通过后，导出 diff、验证报告与复现命令；未通过则同样保留候选实现、完整失败证据和停止原因。

流程应有可调用入口。CLI 名称由实现决定，但文档必须给出真实可执行命令；计划中的示例不得写成已有功能。

## 独立验证与写入边界

- Agent 可修改的是候选 adapter、候选测试、配置和相应说明。官方题目、答案、评分规则、独立验收文件不属于它的修复范围。
- 独立验证由控制器运行，使用预先冻结的正反例；不能只运行 Agent 自己生成的测试。
- 候选代码和验证命令在独立执行沙箱中运行。验证结果作为诊断反馈，受保护输入的原件不交给 Agent 修改。
- 验证前后核对源数据与独立规则哈希。发现修改受保护文件、越界路径或缺少必要版本信息，明确记失败。
- 正确输出必须得预期分；空输出、错误输出必须失败；不能靠“所有样本都给满分”通过验证。
- 不自动复制候选代码覆盖正式实现，不自动修改官方答案、不自动合并／发布。导出完整、可审阅的变更，由人评审接入。

## 交付与归档

每次尝试保存：源版本与哈希、实际模型身份、提示词／工具版本、预算、每步模型与工具记录、生成文件清单及哈希、逐轮验证结果、停止原因、最终 diff 和复现命令。

验证报告至少区分：生成失败、导入／依赖失败、字段或任务协议错误、评分正反例失败、环境故障、预算耗尽、等待人工判断。不要都归为模型能力不足。

在同一套模型／任务接口下，最终候选 adapter 应能加载稳定样本 ID、记录数据版本、运行 MockModel 正反例并保存 manifest；评分行为进入 describe 指纹。

## 最小回归测试

1. 合法 adapter 一次生成后通过独立验证。
2. 第一轮字段映射或导入出错，Agent 收到诊断后第二轮修复成功。明确断言存在反馈与再次生成。
3. Agent 自测通过，但独立错误输出仍被判满分，独立验证必须拒绝。
4. 尝试改答案、评分规则、受保护验收文件或写到候选范围外，被拒绝并记录原因。
5. 修复次数、时间／token 预算耗尽后停止，已完成轨迹和文件保留。
6. 环境故障与代码／评分错误分别记录。
7. 相同源版本、配置和已保存响应能复核结果；更换源数据或评分规则会改变指纹，不静默复用旧验证。
8. 可选依赖缺失只跳过相关用例；现有 run、compare、rescore、verify、Judge 回归保持通过。

以上均可用 MockModel 和假沙箱测试。不要为了开发测试在四核云端部署 Ollama。

## 提交与验收顺序

第一批：规格、隔离候选工作区、独立验证器与结构化报告。

第二批：接入 Agent 循环、诊断反馈、有限修复、轨迹归档和可执行入口。

第三批：一个完整候选 adapter 的端到端 MockModel 演示、使用文档与 PR，交 Codex 复评。

随后在本地或外部 API 上，让真实 Agent 接入一个固定版本的小任务集，由人工审查最终 diff。未实际运行前，状态写“工作流与 MockModel 验收完成、真实接入待验证”。自建样例只证明流程，不冒充已经自动适配新的公开 Benchmark。

每轮按仓库要求写中文 progress 文档，更新索引与路线图。PR 应明确哪些已验证、哪些依赖真实模型／环境尚未验证。
