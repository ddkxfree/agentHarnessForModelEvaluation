## O1 [P1] 默认验证器没有隔离候选代码的宿主文件访问

位置：`onboard/validator.py:58-81`、`123`、`152-181`；`onboard/check.py::Checker.load`。

默认 SubprocessExecutor 只换工作目录、清理环境变量并启动宿主 Python。静态导入白名单包含 pathlib，子进程仍可访问宿主文件；候选自测也直接在宿主子进程中执行。

实际复现：在正确 adapter 的 pathlib 导入之后，加一条 Path 写入语句，目标为候选目录之外、评审专用临时目录内的哨兵文件。

```text
validate.passed = True
validate.category = None
outside_file_created = True
```

没有复杂攻击，仅一次普通文件写入就越过候选目录边界且验证通过。环境变量清理不等于文件系统隔离。progress/25 已披露子进程限制，但它仍不满足阶段八指引中的执行隔离与越界拒绝要求。

补修验收：真实模型候选默认使用具备执行边界的容器／等效沙箱，只提供必要副本或只读输入，限制网络与资源，清理进程；宿主外部文件和正式仓库不能写。可信脚本化演示可保留显式的子进程执行方式，但不能作为未知候选代码的默认隔离保证。adapter 和生成的自测两条路径都要验证越界访问被拒绝。

## O2 [P1] 字段映射错误、答案泄漏到题目仍会通过独立验证

位置：`onboard/check.py:110-156`、`160-215`。

协议检查验证 ID、版本、加载非空等条件；正反例用 MockModel 直接给出预设输出，不会检查候选 adapter 实际发给模型的题目是否正确。

实际复现：把正确 adapter 的 input 从“该国家的首都是什么”改成该行的 capital 字段，target／scorer 保持原样。

```text
input = r["capital"]
validate.passed = True
17 acceptance cases passed
```

这种 adapter 把答案当成题目交给模型，未完成正确字段映射，却通过全部当前验收。它不需要修改答案文件或验证器。

补修验收：独立验收必须覆盖冻结的样本字段语义和模型实际输入，不止是 ID 和 scorer 正反例。首个小任务可明确要求预期 input／target／必要 metadata，并检查 Solver 构造的 prompt；至少覆盖空 input、target 当 input、漏掉问题字段、错误目标以及两次加载 ID 相同但内容变化。Agent 自己生成的字段映射和自测不能作为唯一预期来源。

## O3 [P2] 整个尝试的总时限只在模型调用前检查

位置：`onboard/agent.py:238-255`、`279-288`、`361-379`、`439-451`。

单次模型调用沿用 generate.timeout，独立验证和自测沿用 validation_timeout_s。全局 time_limit_s 只在下一次 _ask 前检查，没有覆盖在途调用、重试与验证，也没有在最终声明 passed 前确认。

实际复现：time_limit_s=0.05 秒，规划立即返回，最后一次写入调用等待 0.15 秒后返回正确 adapter。实际耗时约 0.686 秒，结果仍为 passed／validated。

补修验收：全局截止时间约束模型等待／退避、独立验证和自测，子阶段使用剩余时间；时间耗尽保留已有文件、轨迹与停止原因，不可在超时后声明成功。若取消执行器，必须终止相关进程／容器，不能仅取消等待后继续后台执行。测试使用异步等待和可取消的验证器，不只模拟“下一次调用前发现超时”。
